# Git Commit

## 手順

1. `git status --short --branch` でリポジトリの状態を確認する。
2. ステージ前に、コミット対象の差分を正確に確認する。
   - 追跡済みファイルの変更は `git diff` で確認する。
   - ステージ後の差分は `git diff --cached` で確認する。
   - 未追跡ファイルは、重要な内容ならファイルを直接読んで確認する。
3. 変更の主目的に合わせて、先頭に置く種別タグを選ぶ。
   - `feat:` ユーザー向け機能や新しい能力の追加
   - `fix:` バグ修正
   - `docs:` ドキュメントやナレッジベースの更新
   - `test:` テストのみの変更
   - `refactor:` 振る舞いを変えないコード整理
   - `chore:` 保守、ツール、依存関係、リポジトリ整備
   - `style:` フォーマットのみの変更
4. タグの後ろに日本語の件名を書く。
   - 形式は `<type>: <日本語の短い要約>` とする。
   - 件名は簡潔にし、タグの後ろはできれば50文字以内に収める。
   - 敬体ではなく常体で書く。
   - 文末に句点を付けない。
5. 理由や背景を残す価値がある場合は本文を追加する。
   - `git commit` では複数の `-m` を使い、件名と本文を空行で分ける。
   - 何をしたかだけでなく、なぜその変更が必要かを書く。
   - 今後の Codex セッションが知るべき文脈を残す。
   - 長い本文は、おおむね72文字前後で折り返す。
6. 依頼されたコミットに属するファイルだけをステージする。
7. `git commit -m "<件名>"` でコミットする。必要なら追加の `-m "<本文>"` を付ける。
8. `git status --short --branch` と `git log --oneline -1` で、コミット後の状態を確認する。

## メッセージ例

```text
docs: 初期ドキュメントを追加
feat: プロジェクト一覧の雛形を追加
fix: 支出登録の入力検証を修正
chore: 開発用設定を整理
```

本文を付ける例:

```bash
git commit \
  -m "docs: 初期ドキュメントを追加" \
  -m "codex-hq の目的、想定構成、運用方針を記録する。" \
  -m "今後の Codex セッションがプロジェクトの役割と言語方針を参照できるようにする。"
```

## 注意点

- 関係ない変更を同じコミットに含めない。
- 作業ツリーを clean に見せるために、ユーザーの変更を勝手に戻さない。
- 作業ツリーに無関係な変更がある場合は、依頼対象のパスだけをコミットする。
- 種別タグが曖昧な場合は、もっとも大きなユーザー視点の意図から保守的に判断する。
- 最終応答では、コミットハッシュと作業ツリーが clean かどうかを伝える。
